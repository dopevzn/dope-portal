# DOPE Portal Supabase Foundation

This folder contains the production database foundation for DOPE Portal, starting with the RecruitLook Hoops tenant.

## Files

- `schema.sql` creates extensions, role enum, tables, timestamps, update triggers, comments, constraints, foreign keys, and indexes.
- `rls.sql` enables and forces Row Level Security, adds Clerk-aware membership helpers, and creates tenant isolation policies.
- `seed.sql` inserts structured RecruitLook Hoops operational seed data.
- `migrations/001_media_files_r2_fields.sql` adds Cloudflare R2 metadata fields to `media_files`.

## Apply Order

Run these files in the Supabase SQL editor or through a migration pipeline using a privileged database role:

```sql
\i supabase/schema.sql
\i supabase/rls.sql
\i supabase/seed.sql
```

Supabase SQL editor users can paste/run each file in the same order.

After the foundation files are applied, run:

```sql
\i supabase/migrations/001_media_files_r2_fields.sql
```

Supabase SQL editor users can paste the migration file and run it once. It is
idempotent for repeated local setup.

## Environment Variables

Local Next.js uses these values from `.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=
CLOUDFLARE_ACCOUNT_ID=
CLOUDFLARE_R2_ACCESS_KEY_ID=
CLOUDFLARE_R2_SECRET_ACCESS_KEY=
CLOUDFLARE_R2_BUCKET_NAME=
CLOUDFLARE_R2_PUBLIC_BASE_URL=
```

Do not commit `.env.local`. The service-role key is server-only and must never be used in Client Components.
R2 access keys are also server-only and are used only by Next.js route handlers.

## Tenant Model

`organizations` is the tenant root. Tenant-owned tables carry:

```sql
organization_id uuid references public.organizations(id) on delete cascade
```

`organization_members` maps Clerk users into organizations and roles:

- `owner`
- `media_director`
- `admin`
- `photographer`
- `videographer`
- `editor`
- `scout`
- `coach`
- `sponsor`
- `viewer`

## RLS Model

RLS is enabled and forced on every table. Policies are scoped to the authenticated role and use:

- `current_clerk_user_id()`
- `is_org_member(organization_id)`
- `is_org_admin(organization_id)`
- `can_read_user_profile(clerk_user_id)`

There are no anonymous public table policies. Tenant rows are readable and writable only by active organization members when requests are made with authenticated Supabase JWTs. Deletes and membership edits are restricted to owner, media director, and admin roles.

The RLS helper expects Supabase requests to receive a JWT where the `sub` claim is the Clerk user id. The current app uses server-only Supabase service-role reads plus explicit RecruitLook `organization_id` filters while Clerk/Supabase JWT handoff is not yet configured. Do not expose the service-role key to Client Components.

## R2 Media Storage

The application writes private media binaries to Cloudflare R2 with this object
key shape:

```text
organizations/{organization_slug}/events/{event_slug}/{asset_type}/{yyyy-mm-dd}/{uuid}-{safe_filename}
```

`media_files.storage_key` and `media_files.r2_key` store the private object key.
The UI does not display the key. Download links are generated by
`/api/media/presign-download` after Clerk auth and RecruitLook tenant filtering.

The upload route captures:

- selected event
- asset type
- visibility
- processing status
- optional creator, athlete, and school metadata
- MIME type
- file size
- Clerk user id

Cloudflare manual setup still required:

- private R2 bucket
- bucket-scoped R2 API token
- CORS rules for local and production app origins
- optional public/custom domain only for intentionally public assets

## Seed Contents

`seed.sql` creates:

- RecruitLook Hoops organization
- 5 venues
- 5 events
- 10 schools
- 3 teams
- 20 athletes
- 8 creators
- 12 assignments
- 6 sponsors
- 25 media file metadata records
- 10 deliverables
- 8 media requests
- 4 sponsor assets
- 6 notifications
- 1 storage usage snapshot
- 2 audit log records

Seed media rows are metadata only. New Upload Center media records are written
for Cloudflare R2 once the R2 environment variables and migration are applied.
